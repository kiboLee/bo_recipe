# PRD: 요리 레시피

- 버전: v1.1 (초안)
- 작성일: 2026-10-11
- 개정일: 2026-10-26 (CMS를 Notion에서 Supabase로 변경)
- 대상: 기획자, 개발자, 콘텐츠 운영자

---

## 1. 개요

### 1.1 프로젝트명
요리 레시피

### 1.2 목적
냉장고에 있는 재료로 만들 수 있는 요리를 초보자도 쉽게 따라 할 수 있도록 1인분 기준 레시피로 제공한다. 콘텐츠는 Supabase 데이터베이스에서 관리하여 운영자가 테이블 편집기로 직접 레시피를 작성·발행할 수 있게 한다.

### 1.3 CMS 선택 이유
- Supabase 테이블 편집기에서 운영자가 코드 없이 레시피를 입력하고 발행 상태를 바꿀 수 있다.
- 별도 관리자 페이지 개발 없이 콘텐츠 운영이 가능하다.
- 무료 플랜으로 시작할 수 있고, 로그인·즐겨찾기 같은 후속 기능을 같은 데이터베이스에 붙일 수 있다.
- 재료 상세와 조리 순서를 JSON 컬럼으로 저장해 화면 데이터와 바로 대응한다.

| 구분 | 설명 | 주요 니즈 |
|---|---|---|

## 4. 기능 요구사항

### 4.1 레시피 목록 (FR-01)
- 발행된 레시피만 카드 형태로 노출한다.
- 카드 항목: 대표 이미지, 제목, 한 줄 설명, 조리 시간, 난이도.
- 재료 멀티 선택 필터: 선택한 재료를 모두 포함하는 레시피를 보여준다(AND 조건).
- 보조 필터: 카테고리, 난이도.
- 정렬: 최신 발행순 기본, 조리 시간순 선택 가능.
- 결과가 없을 때 빈 상태 메시지와 필터 초기화 버튼을 노출한다.

### 4.2 레시피 상세 (FR-02)
- 대표 이미지, 제목, 설명을 상단에 표시한다.
- 메타 정보: 1인분 기준 표시, 조리 시간, 난이도, 카테고리.
- 재료 목록: 1인분 기준 분량을 표시한다.
- 조리 순서: `steps` 항목을 순서(`order`)대로 번호 목록으로 렌더링한다.
- PDF 다운로드 버튼을 제공한다(FR-03).
- 존재하지 않거나 미발행인 슬러그 접근 시 404를 반환한다.

### 4.3 PDF 다운로드 (FR-03)
- 상세 페이지의 "PDF 다운로드" 버튼으로 해당 레시피를 PDF로 저장한다.
- PDF 포함 항목: 제목, 대표 이미지, 메타 정보, 재료, 조리 순서.
- 파일명: `{슬러그}.pdf`.
- 한글 폰트를 포함해 깨지지 않아야 한다.

### 4.4 콘텐츠 관리 (FR-04, Supabase)
- 레시피 테이블의 컬럼은 6장(데이터 모델)을 따른다.
- `status`가 "발행"인 행만 사이트에 노출한다(쿼리 필터와 RLS 정책으로 함께 보장).
- DB 수정 후 일정 시간(ISR 재검증 주기) 내에 사이트에 반영된다.
- 필수 값 누락 시(제목, 슬러그, 재료 상세) 목록에서 제외하고 서버 로그에 경고를 남긴다.

### 4.5 반응형 (FR-05)
- 모바일(360px 이상), 태블릿, 데스크톱을 지원한다.
- 카드 그리드: 모바일 1열, 태블릿 2열, 데스크톱 3열 이상.
- 필터는 모바일에서 접을 수 있는 패널로 표시한다.
- 가로 스크롤 없이 모든 기능을 사용할 수 있어야 한다.

### 4.6 공통 (FR-06)
- 라이트/다크 모드를 지원한다.
- 로딩, 빈 결과, 에러 상태 UI를 제공한다.
- 주요 이미지는 `next/image`로 최적화한다.

## 6. 데이터 모델 (Supabase 테이블: recipes)

| 컬럼명 | 타입 | 필수 | 설명 |
|---|---|---|---|
| 제목 | `title` text | 예 | 레시피명 |
| 슬러그 | `slug` text (unique) | 예 | URL 식별자 (영문 소문자, 하이픈) |
| 설명 | `description` text | 아니오 | 한 줄 소개 |
| 대표 이미지 | `image_url` text | 예 | 목록·상세·PDF에 사용 |
| 재료 | `ingredient_tags` text[] | 예 | 필터용 태그 (예: 계란, 양파, 두부) |
| 재료 상세 | `ingredient_items` jsonb | 예 | 1인분 기준 재료와 분량 (`{name, amount}` 배열) |
| 난이도 | `difficulty` text | 예 | 쉬움 / 보통 |
| 조리시간 | `cook_time_minutes` int | 예 | 분 단위 |
| 카테고리 | `category` text | 아니오 | 한식 / 양식 / 간단식 등 |
| 상태 | `status` text | 예 | 초안 / 발행 (발행만 노출) |
| 발행일 | `published_at` timestamptz | 예 | 정렬 기준 |
| 조리 순서 | `steps` jsonb | 예 | `{order, text}` 배열, `order` 순서대로 표시 |

- 기본 키 `id`는 자동 생성된다.
- 조리 순서는 `steps` 컬럼에 저장한다.
- 재료 태그는 `ingredient_tags`에 저장하며, 신규 재료를 입력하면 바로 필터에 반영된다.

## 7. 화면 구성

| 경로 | 화면 | 주요 구성 |
|---|---|---|
| `/recipes` | 레시피 목록 | 헤더, 재료 필터, 카테고리·난이도 필터, 정렬, 카드 그리드, 빈 상태 |
| `/` | 홈 | `/recipes`로 리다이렉트 |
| `/recipes/[slug]` | 레시피 상세 | 대표 이미지, 제목·설명, 메타 정보, 재료 목록, 조리 순서, PDF 버튼 |
| `/not-found` | 404 | 목록으로 돌아가기 링크 |

공통 요소: 헤더(로고, 테마 전환), 푸터, 반응형 레이아웃.

## 8. 기술 스택

| 영역 | 선택 | 비고 |
|---|---|---|
| 프론트엔드 | Next.js 16 (App Router), TypeScript | 프로젝트 기준 버전 16.3.8. 요청 문서의 15 대신 실제 설치 버전 사용 |
| 렌더링 | Server Components 우선, ISR | 목록·상세 정적 생성 후 재검증 |
| 데이터 | Supabase (Postgres), `@supabase/supabase-js` | 서버 측에서 publishable 키로 조회, RLS로 발행 레시피만 공개 |
| 스타일 | Tailwind CSS v4, shadcn/ui | 다크모드는 `dark:` 접두사 |
| 아이콘 | Lucide React | |
| PDF | 서버 측 PDF 생성 라이브러리 (구현 단계에서 확정) | Route Handler에서 생성 |
| 배포 | Vercel (권장) | |

### 8.1 계층 구조
- `app/` (라우트·화면) → `services/` (유스케이스) → `repositories/` (Supabase 호출, 행→DTO 매핑) → `dto/` (응답 타입)
- 조리 순서·재료 상세 JSON 값의 검증과 가공은 `services/`에서 처리한다.

## 9. 범위

### 9.1 MVP 포함
- Supabase 연동 (발행 상태 레시피만 조회)
- 목록 화면 + 재료·카테고리·난이도 필터
- 상세 화면 (메타, 재료, 조리 순서)
- PDF 다운로드
- 반응형 레이아웃, 다크모드
- ISR 캐싱 및 재검증

### 9.2 MVP 제외 (후속 버전)
- 검색어 자동완성
- 즐겨찾기, 사용자 계정
- 인분 수 조절 (1인분 고정)
- 다국어 지원
- 댓글, 평점
- 관리자 전용 웹 화면 (Supabase 테이블 편집기로 대체)

## 10. 구현 단계

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 1. 기반 | 환경 변수(NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY), Supabase 클라이언트, DTO, 행→DTO 매핑 | 샘플 데이터에서 목록 데이터 조회 성공 |
| 2. 목록 | 카드 그리드, 재료·카테고리·난이도 필터, 빈 상태 | 필터 조합 결과가 DB와 일치 |
| 3. 상세 | 메타 정보, 재료, 조리 순서 렌더링, 404 처리 | 발행 레시피 상세 정상 표시, 미발행 404 |
| 4. PDF | Route Handler에서 PDF 생성, 한글 폰트 적용 | 다운로드 파일 한글 깨짐 없음 |
| 5. 마감 | 반응형, 접근성, 다크모드, SEO 메타 | 모바일 가로 스크롤 없음, 접근성 점검 통과 |
| 6. 배포 | Vercel 배포, 재검증 설정, 운영 가이드 작성 | 운영자가 DB에 등록한 레시피가 사이트에 반영 |
