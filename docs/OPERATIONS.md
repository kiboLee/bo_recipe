# 운영 가이드: 레시피 등록과 반영 확인

운영자가 Supabase 테이블 편집기에서 레시피를 등록하고 발행하는 절차입니다. 개발 지식 없이 따라 할 수 있도록 작성했습니다.

목표는 등록부터 사이트 반영까지 30분 이내입니다 (PRD 2장).

---

## 1. 등록 절차

1. Supabase 대시보드에서 프로젝트를 엽니다.
2. 왼쪽 메뉴의 **Table Editor**에서 `recipes` 테이블을 선택합니다.
3. **Insert row**를 눌러 새 행을 추가하고, 아래 표의 값을 입력합니다.
4. `status`를 **발행**으로 설정하고 저장합니다. `초안`으로 두면 사이트에 노출되지 않습니다.
5. 반영을 기다립니다 (아래 "반영 시점" 참고).

---

## 2. 컬럼 입력 규칙

| 컬럼 | 필수 | 입력 방법 | 예시 |
|---|---|---|---|
| `title` | 예 | 레시피 이름 | `계란 볶음밥` |
| `slug` | 예 | 영문 소문자와 하이픈만 사용, 다른 레시피와 겹치지 않게 | `egg-fried-rice` |
| `description` | 아니오 | 한 줄 소개 (비워도 됨) | `남은 밥과 계란만 있으면 10분 안에 완성` |
| `image_url` | 예 | 아래 "이미지 규칙" 참고 | `https://<project-ref>.supabase.co/storage/v1/object/public/...` |
| `ingredient_tags` | 예 | 필터용 재료 태그 배열 (아래 "재료 태그 규칙" 참고) | `{계란, 양파, 밥}` |
| `ingredient_items` | 예 | 1인분 기준 재료와 분량 (JSON, 아래 형식) | `[{"name":"계란","amount":"2개"}]` |
| `difficulty` | 예 | `쉬움` 또는 `보통` | `쉬움` |
| `cook_time_minutes` | 예 | 조리 시간, 분 단위 숫자 | `15` |
| `category` | 아니오 | `한식`, `양식`, `간단식` 중 하나 (비우면 카테고리 필터에서 제외) | `간단식` |
| `status` | 예 | `초안` 또는 `발행` (발행만 노출) | `발행` |
| `published_at` | 예 | 발행 날짜와 시각. 목록의 기본 정렬 기준 | `2026-10-27 09:00:00+09` |
| `steps` | 예 | 조리 순서 (JSON, 아래 형식) | `[{"order":1,"text":"양파를 썬다."}]` |

### 재료 상세(`ingredient_items`) 형식

```json
[
  { "name": "밥", "amount": "1공기" },
  { "name": "계란", "amount": "2개" }
]
```

- `name`과 `amount` 두 항목이 모두 있어야 합니다. 하나라도 비어 있으면 그 재료는 제외됩니다.
- 재료 상세가 하나도 없는 레시피는 목록과 상세 모두에서 제외됩니다.

### 조리 순서(`steps`) 형식

```json
[
  { "order": 1, "text": "양파와 대파를 잘게 썬다." },
  { "order": 2, "text": "달군 팬에 기름을 두르고 계란을 스크램블한다." }
]
```

- `order`는 1부터 시작하는 정수입니다. 화면에는 `order` 순서대로 표시됩니다.
- `order` 번호가 1부터 빠짐없이 이어지지 않으면 로그에 경고가 남지만, 표시는 됩니다. 가능하면 1, 2, 3 순서로 입력하세요.
- `text`가 비어 있는 단계는 제외됩니다.

### 재료 태그 규칙 (`ingredient_tags`)

- 필터 목록은 모든 발행 레시피의 태그를 모아 만듭니다. 같은 재료를 `계란`과 `달걀`처럼 다르게 쓰면 필터가 둘로 나뉩니다.
- 새 레시피를 입력하기 전에 기존 태그를 먼저 확인하고 같은 표기를 사용하세요.
- 표준 태그 목록은 아직 정해지지 않았습니다 (PRD 12장 오픈 이슈). 협의 후 이 문서에 추가합니다.

---

## 3. 이미지 규칙

- `image_url`은 **Supabase Storage의 공개 주소**(`https://<project-ref>.supabase.co/...`)를 사용합니다.
- 다른 호스트의 주소, `http://` 주소, 비어 있는 값은 사이트에서 기본 이미지로 대체됩니다. 이 경우 서버 로그에 경고가 남습니다.
- 이미지 용량 권장 기준은 아직 정해지지 않았습니다 (PRD 12장 오픈 이슈). 지금은 가벼운 사진을 쓰고, 이미지가 깨지면 주소가 만료되었는지 먼저 확인하세요.

---

## 4. 반영 시점

- 목록(`/recipes`)은 요청할 때마다 최신 데이터를 가져옵니다.
- 상세 페이지는 **10분 주기로 갱신**됩니다. 수정 후 최대 10분 뒤에 바뀝니다 (`app/recipes/[slug]/page.tsx`의 `revalidate = 600`).
- **새로 발행한 레시피는 재배포 후에 상세가 열립니다.** 빌드 때 만든 페이지만 있기 때문입니다. 목록에는 바로 보이지만 상세는 재배포 전까지 404입니다.
- 발행 후에는 **Deploy Hook**을 호출해 재배포합니다. 호출 주소는 개발자가 Vercel 프로젝트 설정에서 만들어 전달합니다. 주소가 없으면 개발자에게 재배포를 요청하세요.
- 재검증 주기를 바꾸려면 개발자에게 요청하세요. 이 값은 환경 변수가 아니라 코드 설정입니다.

---

## 5. 반영 확인 절차

1. 사이트 `/recipes`에 새 레시피 카드가 보이는지 확인합니다.
2. 카드를 눌러 상세 페이지가 열리는지 확인합니다.
3. 상세 하단의 **PDF 다운로드** 버튼으로 파일이 받아지는지 확인합니다.
4. 카드가 보이지 않으면 아래 "문제 해결"을 확인합니다.

---

## 6. 문제 해결

| 증상 | 원인 | 조치 |
|---|---|---|
| 목록에 안 보임 | `status`가 `초안`, 또는 재료 상세가 비어 있음 | `status`를 `발행`으로 바꾸고, `ingredient_items`에 재료를 넣습니다 |
| 상세가 404 | 슬러그 오타, `status`가 `초안`, 또는 발행 후 재배포 전 | 슬러그 철자와 발행 상태를 확인하고, Deploy Hook으로 재배포합니다 |
| 수정했는데 그대로 | 재검증 주기(최대 10분) 이내 | 10분 뒤 다시 확인합니다 |
| 사진 대신 기본 이미지 | 허용되지 않은 주소 형식 | Supabase Storage 공개 주소로 바꿉니다 |
| 목록 전체가 비어 있음, "불러오는 중" 또는 오류 화면 | Supabase 연결 실패(프로젝트 일시 중지 포함) | Supabase 프로젝트 상태를 확인하고, 개발자에게 알립니다 |
| PDF가 오류 | 이미지 주소 만료 또는 PDF 생성 실패 | 이미지 주소를 교체하고 다시 시도합니다. 계속 실패하면 개발자에게 알립니다 |

---

## 7. 서버 로그 확인

잘못된 데이터는 화면에서 제외되거나 기본값으로 대체되고, 서버 로그에 아래 형식으로 남습니다.

```
[recipe-repository] 레시피 id=<번호> slug=<슬러그>: <사유>
```

- 사유 예시: `재료 상세 잘못된 항목 1건 제외`, `조리 순서 번호가 1부터 연속하지 않음`, `재료 상세가 없어 목록에서 제외`
- 확인 방법: Vercel 대시보드에서 프로젝트를 열고 **Logs**에서 `recipe-repository`로 검색합니다.
- 로그에 경고가 있으면 해당 레시피의 `id`를 찾아 `ingredient_items`, `steps`, `image_url`을 수정합니다.

---

## 8. 필수 컬럼 누락 시 증상 요약

| 누락 컬럼 | 증상 |
|---|---|
| `ingredient_items` (또는 유효한 재료 없음) | 목록과 상세 모두에서 제외 |
| `steps` | 상세에 조리 순서가 나오지 않음 |
| `slug` | 상세 주소를 만들 수 없음 |
| `status`가 `발행`이 아님 | 목록과 상세 모두에서 제외 |
| `image_url` 비어 있음 | 기본 이미지로 표시 |

---

## 9. 개발자에게 전달할 때

다음 정보를 함께 보내 주세요.

- 레시피 `id`와 `slug`
- 증상 (목록에 없음, 404, 이미지 깨짐, PDF 오류 중 무엇인지)
- Vercel 로그에서 찾은 `[recipe-repository]` 또는 `[recipe-pdf]` 메시지
