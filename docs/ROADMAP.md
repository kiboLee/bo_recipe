# 요리 레시피 개발 로드맵

냉장고 속 재료로 만들 수 있는 1인분 레시피를 초보자도 따라 할 수 있게 제공하며, 콘텐츠는 Supabase 테이블 편집기에서 운영자가 직접 작성·발행하는 서비스입니다.

## 개요

요리 레시피는 요리 초보자와 자취·직장인을 위한 **재료 기반 1인분 레시피 서비스**로 다음 기능을 제공합니다:

- **재료 기반 레시피 목록 (FR-01)**: 발행된 레시피를 카드로 보여주고, 선택한 재료를 모두 포함하는 레시피를 AND 조건으로 필터링
- **레시피 상세 (FR-02)**: 1인분 메타 정보, 재료 목록, DB의 조리 순서(`steps`) 제공
- **PDF 다운로드 (FR-03)**: 한글이 깨지지 않는 레시피 PDF 저장 (`{슬러그}.pdf`)
- **콘텐츠 관리 (FR-04)**: Supabase `recipes` 테이블을 콘텐츠 저장소로 사용, ISR(10분) 재검증으로 반영
- **반응형 및 공통 UI (FR-05, FR-06)**: 모바일 360px 이상 지원, 라이트/다크 모드, 로딩·빈 결과·에러 상태

## 개발 워크플로우

1. **작업 계획**

- 기존 코드베이스를 학습하고 현재 상태를 파악
- 새로운 작업을 포함하도록 `ROADMAP.md` 업데이트
- 우선순위 작업은 마지막 완료된 작업 다음에 삽입

2. **작업 생성**

- 기존 코드베이스를 학습하고 현재 상태를 파악
- `/tasks` 디렉토리에 새 작업 파일 생성 (명명 형식: `XXX-description.md`, 예: `001-setup.md`)
- 고수준 명세서, 관련 파일, 수락 기준, 구현 단계 포함
- **API/비즈니스 로직 작업 시 "## 테스트 체크리스트" 섹션 필수 포함 (Playwright MCP 테스트 시나리오 작성)**
- 예시는 `/tasks` 디렉토리의 마지막 완료 작업을 참조하며, 신규 작업 문서에는 빈 체크박스와 변경 사항 요약을 두지 않음

3. **작업 구현**

- 작업 파일의 명세서를 따름
- 계층 구조 `app/ → services/ → repositories/ → dto/`를 준수 (화면 로직은 `app/`, 유스케이스는 `services/`, Supabase 호출과 행→DTO 매핑은 `repositories/`, 응답 타입은 `dto/`)
- Next.js 16 API는 구현 전 `node_modules/next/dist/docs/`의 관련 가이드를 확인 (AGENTS.md 지침)
- **API 연동 및 비즈니스 로직 구현 시 Playwright MCP로 테스트 수행 필수**
- 각 단계 후 작업 파일 내 단계 진행 상황 업데이트
- 구현 완료 후 Playwright MCP를 사용한 E2E 테스트 실행
- 테스트 통과 확인 후 다음 단계로 진행
- 각 단계 완료 후 중단하고 추가 지시를 기다림

4. **로드맵 업데이트**

- 로드맵에서 완료된 작업을 ✅로 표시하고 `See: /tasks/XXX-xxx.md` 참조를 추가

## 오픈 이슈

PRD 12장에서 정리된 미결정 사항과 해당 Task입니다. 각 이슈는 확정 전까지 해당 Task를 진행하지 않거나 기본값으로 진행합니다.

- **재료 태그 표준 목록 (운영자와 협의)**
  - 영향 Task: 010 (필터 품질), 012 (재료 필터), 024 (운영 가이드)

- **PDF 레이아웃 시안 (구현 단계 4에서 확정)**
